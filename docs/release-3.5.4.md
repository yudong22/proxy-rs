# proxy-rs v3.5.4 发布说明：会话可在浏览器中打开

> 版本：**3.5.4**（上一版 3.5.3）
> 一个新功能，加上把它真正接通所需的权限与路由梳理。

---

## 1. 会话列表：在浏览器打开

会话行的右上角多了一个按钮：桌面端是 **↗ 在浏览器打开**，服务器控制台是 **⧉ 复制链接**。
详情页顶部也有一份，位置与「详情」按钮并列。

点开之后浏览器落在：

```
http://127.0.0.1:<本机控制台端口>/admin/#sessions/<uuid>
```

也就是说**不只是打开控制台，而是直接落到那个会话**：列表已加载、该行已选中、时间线已展开。
这让一个会话变成可分享、可收藏、可刷新后仍在原处的地址。

### 为什么要分两种形态

同一个前端跑在三个地方，其中两个的答案完全不同：

| 环境 | 按钮 | 行为 | 为什么 |
|---|---|---|---|
| 桌面 App 的控制台 | ↗ 打开 | 调系统默认浏览器 | 窗口是 Tauri 的，用户想要的是"用我自己浏览器看" |
| 服务器控制台 | ⧉ 复制链接 | 写入剪贴板 | **你已经在浏览器里**，再"打开"一次没有意义 |
| 无后端预览 | 不渲染 | — | 没有会话可开 |

服务器形态刻意**不发那个 RPC**：在服务器上调它只会换来一条错误提示，不如直接给出真正有用的
动作。剪贴板写入有三层兜底（`navigator.clipboard` → 离屏 `textarea` + `execCommand` →
toast 里给出链接让人手抄），因为局域网 http 是非安全上下文，第一层经常不可用；任何一层失败
都不会谎报「已复制」。

## 2. 打开权限是怎么守住的

这是本功能真正的难点，也是花时间最多的地方——它把「让用户的浏览器打开一个地址」这个能力
引入了控制台，而控制台的 RPC 端点对任何已登录会话都是开放的。

### 只接受会话 id，URL 由后端拼

前端调用的是 `open_session_in_browser { id }`。**入参里没有任何 URL、host 或端口**，服务端
也只读 `id`（额外的 `url` / `host` / `port` / `href` 字段一律忽略，有测试专门反向证明）。

如果接受调用方给的 URL，那么控制台里的任意脚本（含将来某次 XSS）就能让**用户的默认浏览器**
去打开 `file:///etc/passwd` 或一个钓鱼站点——用户点的是一个自己信任的按钮，落地却由攻击者
决定。所以客户端只能说「哪个会话」，其余由网关决定。

全链有**三处独立校验**，任何一处都不单独承担安全边界：

1. `session_console_url()` —— 全仓库唯一产出该 URL 的地方，id 必过严格 UUID 校验；
2. `open_session_in_browser()` 出口 —— 再校验一次形状；
3. `src-tauri` 里 spawn 平台启动器**之前** —— 用同一个公开的 `is_console_url()` 再校验一次。

`is_console_url()` 是**前缀 + 形状**校验，不是子串包含。这一点有实际区别：子串判断会放行
`file:///tmp/x?next=http://127.0.0.1:4123/admin/`。实测这几种都会被拒：

```
false  file:///etc/passwd
false  http://127.0.0.1.evil.example:4123/admin/
false  http://user@127.0.0.1:4123/admin/
false  http://127.0.0.1:4123/administrator/
false  http://127.0.0.1:0/admin/
```

### 端口必须取控制台端口，不是数据面端口

桌面端有**两个** listener：数据面在 `port`，控制台在 `port + 1 … +9`（取第一个可用）。
`open_session_in_browser` 用的是 `AppContext.console_port`，**不是** `bound_port`。

这个区别很要紧，因为出错时的表现是「打开了，但空白/404」而不是「打开失败」——两个端口只差 1，
看起来像功能没做完，实际上是把 `/admin/` 指到了一个不提供它的端口上。

控制台端口是**异步绑定**的：注册钩子的那一刻它往往还是 `0`。所以端口通过一个返回 `u16` 的
钩子在**调用时**读取，而不是在注册时快照。`0` 意味着"控制台还没起来"，此时明确报错
「控制台未就绪」，绝不拼出 `:0`、也绝不回落到数据面端口。

### 深链接与登录页

深链接要能跨过登录页才有意义。`#sessions/<uuid>` 因此被加进登录表单 `next` 字段的白名单。

那个白名单原本只允许四个裸标签名，存在的理由是**防开放重定向**（`next` 是一个表单字段）。
扩展时保持了同样的严格性：新增的形态只能是 `sessions/` 加一个**严格小写 hex UUID**，因此
它仍然表达不了 scheme、host 或路径穿越。真实网关上实测，以下输入全部回落 `/admin/`：

```
https://evil.example/x                          -> /admin/
//evil.example                                  -> /admin/
sessions/../../etc/passwd                       -> /admin/
sessions/ABCDEF01-2345-6789-ABCD-EF0123456789   -> /admin/
sessions/notauuid                               -> /admin/
../admin                                        -> /admin/
```

而合法的深链接确实穿过登录：

```
POST /admin/login  next=sessions/828b064c-…
=> 303  location: /admin/#sessions/828b064c-…
   Set-Cookie: proxy_rs_admin=…; HttpOnly; SameSite=Strict; Path=/admin
```

### 浏览器打开后为什么不用再登录

桌面 App 的控制台本来就没有令牌可输（进程即操作者）。浏览器从地址栏打开
`http://127.0.0.1:<console>/admin/` 时，`serve_page` 的桌面自动铸会话逻辑会命中
（loopback + 导航），直接下发会话 cookie。所以点击按钮 → 浏览器 → 已登录的控制台 → 定位到
那个会话，中间没有登录步骤。

## 3. 还有一个前提被顺手确认了

`#sessions/<uuid>` 能被识别，要求标签页路由只看 hash 的**第一段**。原来的实现拿整串 hash 去
和标签名比对，于是 `#sessions/<uuid>` 会在首次渲染时被判定为"未知标签"并重写成 `#sessions`——
深链接当场丢失，表现为"点了打开，但只到了会话列表第一页"。

现在路由切出 `/` 之前的部分作为标签名，id 原样留给会话视图；`switchTab` 的比较也只看标签段，
否则它同样会在首帧把深链接覆盖掉。会话视图在做完 UUID 形状校验后才去选中，形状不对就当作
没有深链接（这是纵深防御，服务端才是边界）。

## 三平台打开命令

| 平台 | 命令 |
|---|---|
| macOS | `open <url>` |
| Linux | `xdg-open <url>` |
| Windows | `cmd /C start "" <url>` |

Windows 那条的空串是 `start` 的**窗口标题**位，必须有：把 URL 放错位置时，`start` 会把下一个
记号当作要打开的目标；又因为我们的 URL 刻意**不带查询参数**，也就不会出现 `&` 被 `cmd` 当成
命令分隔符的情况。

其他平台返回错误而不是静默成功——一个"点了没反应"的成功返回比报错更难查。
