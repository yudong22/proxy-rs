Proxy RS 网关

OpenAI 兼容的多协议 AI 代理 · 需访问密钥

接入地址

https://api.wuba.site

访问密钥

所有请求都必须携带访问密钥。以下三种请求头任选其一，效果相同：

请求头适用于
x-proxy-rs-key: <key> 通用，最明确
Authorization: Bearer <key> OpenAI SDK、ANTHROPIC_AUTH_TOKEN
x-api-key: <key> Claude Code、多数 Anthropic 客户端
大多数客户端只需填两项：接口地址 https://api.wuba.site 和 API Key。 不需要额外配置自定义请求头 —— 上表后两种就是客户端本来就会发送的标准头。

快速验证

curl https://api.wuba.site/v1/models \
  -H "x-api-key: <你的密钥>"

返回模型列表即为成功。缺密钥或密钥错误返回 401。

常见客户端配置

Claude Code

export ANTHROPIC_BASE_URL=https://api.wuba.site
export ANTHROPIC_AUTH_TOKEN=<你的密钥>

OpenAI SDK（Python）

from openai import OpenAI

client = OpenAI(
    base_url="https://api.wuba.site/v1",
    api_key="<你的密钥>",
)

resp = client.chat.completions.create(
    model="hy4std",            # ← 见上方「可用模型」
    messages=[{"role": "user", "content": "你好"}],
)

Codex CLI（~/.codex/config.toml）

[model_providers.proxy_rs]
base_url = "https://api.wuba.site/v1"
wire_api = "responses"

注意事项

  • 只支持 HTTPS。用 http:// 访问会被 308 重定向到 HTTPS。
  • 密钥请勿外传。它等同于你的账号使用权，泄露后他人可消耗你的额度。
  • 观测接口不对外。/api/* 与 /metrics 在本域名下统一返回 404，属正常现象。
  • 流式响应（SSE）已配置为不缓冲，首 token 会尽快到达。
遇到 401 时，响应体会包含具体原因：missing_key（未携带密钥）、 invalid_key（密钥不存在）、account_disabled（密钥已被停用）。 可据此判断是配置问题还是密钥被吊销。
